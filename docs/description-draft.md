## 1. Что это

ИИ-агент для руководителя цифрового продукта в виде папки с правилами, знаниями, навыками, субагентами, хуками и скриптами. Работает в Claude Code, правила продублированы в AGENTS.md для Cursor и Codex. Ведёт от размытого запроса к картине ситуации, вариантам, согласованным продуктовой и коммуникационной стратегиям и плану проверки. После решения хранит основания, сроки обязательств и пересматривает выводы при новых данных.

## 2. Архитектура

Слои хранятся раздельно:
1. Постоянные правила: CLAUDE.md и AGENTS.md. Порядок шагов, доказательность, безопасность, экономичность.
2. Методики: knowledge/, девять файлов. Агент читает нужный файл перед шагом, а не все сразу.
3. Процедуры: .claude/skills/, девять навыков. Один навык на шаг.
4. Субагенты: .claude/agents/, три штуки.
5. Хуки: .claude/settings.json, три события.
6. Проект: projects/<имя>/. Постановка, источники, реестр сведений, состояние, решения, журнал, расходы, результаты.

Процесс: intake, collect, research, options, выбор человека, strategy, verify-plan, decision-log. Навык revise запускается при новых или отозванных данных. Навык interview-sim запускается по запросу или при нехватке гипотез.

### Контекст и знания

Состояние задачи лежит в state.md. Хук SessionStart загружает его в начале сеанса, поэтому работа продолжается в новом чате без повтора. Реестр evidence.csv хранит каждое сведение со статусом (факт, гипотеза, прогноз, синтетика, отозвано), источником, датой и достоверностью. Прежние ответы агента не считаются источником. Синтетические ответы не доказывают спрос.

### Маршрутизация по стоимости

Сбор сведений: субагент collector на Haiku, помечает каждое сведение как «открыта» (страница прочитана) или «сниппет». Модельные респонденты: субагент respondent на Haiku. Критика вариантов и стратегий: субагент critic на Sonnet. Анализ, варианты и стратегия: основной агент на Sonnet.

### Хуки

1. SessionStart: загрузка состояния проекта.
2. PostToolUse: запись действий в log.md.
3. Stop: подсчёт токенов и стоимости из транскрипта в costs.csv по ценам из scripts/prices.json.

### Скрипты

add_evidence.py добавляет сведение в реестр. impact.py находит выводы, которые опираются на отозванное сведение. decisions_check.py показывает просроченные обязательства и отозванные основания. costs_report.py считает расходы по сеансам. check_secrets.sh проверяет репозиторий на секреты перед коммитом.

## 5. Реализованные возможности дополнительного уровня

1. Интервью и модельные респонденты: навык interview-sim, субагент respondent, статус «синтетика».
2. Анализ данных: воспроизводимые расчёты в calc/ проекта, результат попадает в реестр со source_type «расчёт».
3. Поддержка решений: decisions.md, обязательства с владельцами и сроками, decisions_check.py.
4. Пересмотр при новых данных: навык revise и impact.py.
5. Маршрутизация: три субагента на разных моделях.
6. Навыки, хуки, субагенты.
7. База знаний: knowledge/, отзыв устаревших записей через статус «отозвано».
8. Переносимость: AGENTS.md, состояние в Markdown и CSV.
9. Сравнение с исходным способом: docs/comparison-with-chat.md.

Не реализовано: работа с изображениями, аудио и видео, анализ интерфейсов, подключение MCP-серверов, специализированные модели-классификаторы.

## 8. Ошибки и помощь человека

Ошибки агента, найденные проверкой:
1. Сообщение обещало «в любой момент» и «со счёта» без источника. Нашёл критик, часть исправлена по оферте МегаФона.
2. Порог удержания противоречил расчёту экономики.
3. Размер группы пилота не позволял увидеть заданный порог эффекта.
4. Часть ссылок не подтверждала утверждения.
5. Первый расчёт использовал цену 300 вместо 199 ₽.

Ошибки в настройке и их исправления:
1. Команды для Linux на Windows (python3, bash).
2. Сбои CSV из-за кавычек при записи через echo: добавлен add_evidence.py.
3. Агент просил разрешение между шагами: добавлено правило 6.
4. Агент предлагал только диагностику: добавлено правило 7.
5. Устаревшая сумма расходов в отчёте: добавлено правило 8.

Помощь человека: выбор варианта на шаге options, настройка Windows, публикация репозитория.

## 9. Ограничения

1. Только открытые источники. Все цифры экономики в демо это прогнозы низкой достоверности с допущениями.
2. Спрос по сегментам основан на модельных респондентах, реальных интервью нет.
3. Владельцы и пороги в демо предложены агентом и помечены как допущения.
4. Сравнение с чатом: один прогон каждого, оценка автора.
5. Агент зависит от Claude Code и моделей Claude. Перенос в другие среды ожидается через AGENTS.md, но проверен только в Claude Code.
6. Скрипты на bash (new_project.sh, check_secrets.sh) на Windows требуют Git Bash.
7. Стоимость считается по транскрипту и может не включать токены последнего хода.
8. Не реализованы работа с изображениями, аудио, видео и MCP.
